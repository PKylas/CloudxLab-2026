Below are the typical steps to code an **agent harness** — the runtime wrapper that lets an AI model plan, call tools, keep state, handle errors, and return results.

## 1. Define the agent’s purpose

Start by deciding what the agent should do.

Examples:

- Answer questions
- Use tools like search, files, databases, APIs
- Write and execute code
- Complete multi-step tasks
- Operate in a constrained environment

Define:

```text
Goal: What should the agent accomplish?
Inputs: What does the user provide?
Outputs: What should the agent return?
Tools: What external actions can it take?
Limits: What is it not allowed to do?
```

---

## 2. Design the harness architecture

A basic agent harness usually has these components:

```text
User input
   ↓
Agent loop
   ↓
LLM call
   ↓
Tool decision
   ↓
Tool execution
   ↓
Observation returned to model
   ↓
Repeat until final answer
```

Core parts:

- **Model interface**
- **Tool registry**
- **Agent loop**
- **Memory or state**
- **Error handling**
- **Logging**
- **Stopping conditions**

---

## 3. Define the agent state

The harness needs to track conversation and execution state.

Example:

```python
state = {
    "messages": [],
    "tool_results": [],
    "steps": 0,
    "max_steps": 10,
    "done": False
}
```

You may also track:

- User ID
- Session ID
- Files
- Intermediate plans
- Tool call history
- Cost/token usage

---

## 4. Create a tool interface

Each tool should have:

- A name
- A description
- An input schema
- A function to execute

Example:

```python
def search_web(query: str) -> str:
    return f"Search results for: {query}"
```

A simple tool registry:

```python
TOOLS = {
    "search_web": search_web
}
```

For production, include schemas:

```python
tools = [
    {
        "name": "search_web",
        "description": "Search the web for information",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {"type": "string"}
            },
            "required": ["query"]
        }
    }
]
```

---

## 5. Write the system prompt

The system prompt defines the agent’s behavior.

Example:

```text
You are a helpful AI agent.

You may use tools when needed.
If you need outside information, call a tool.
If you have enough information, answer the user directly.
Do not invent tool results.
Stop when the task is complete.
```

You can also include rules such as:

```text
Never call tools unnecessarily.
Ask for clarification if the task is ambiguous.
Use at most 5 tool calls.
Return concise final answers.
```

---

## 6. Implement the LLM call

Create a function that sends messages and tool definitions to the model.

Pseudo-code:

```python
def call_model(messages, tools):
    response = client.chat.completions.create(
        model="your-model",
        messages=messages,
        tools=tools
    )
    return response
```

The exact code depends on the model provider you use.

---

## 7. Implement the agent loop

The loop is the heart of the harness.

Basic flow:

```python
while not done:
    response = call_model(messages, tools)

    if response contains final answer:
        return final answer

    if response contains tool call:
        run tool
        append tool result to messages
        continue

    if max steps exceeded:
        stop
```

Example skeleton:

```python
def run_agent(user_input):
    messages = [
        {
            "role": "system",
            "content": "You are a helpful AI agent that can use tools."
        },
        {
            "role": "user",
            "content": user_input
        }
    ]

    max_steps = 10

    for step in range(max_steps):
        response = call_model(messages, tools)

        message = response.choices[0].message
        messages.append(message)

        if not message.tool_calls:
            return message.content

        for tool_call in message.tool_calls:
            tool_name = tool_call.function.name
            tool_args = json.loads(tool_call.function.arguments)

            result = TOOLS[tool_name](**tool_args)

            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": str(result)
            })

    return "Agent stopped because it reached the maximum number of steps."
```

---

## 8. Add tool execution safety

Before running tools, validate:

- Tool name exists
- Arguments match schema
- User has permission
- Tool call is safe
- Rate limits are respected

Example:

```python
if tool_name not in TOOLS:
    result = f"Error: unknown tool {tool_name}"
else:
    result = TOOLS[tool_name](**tool_args)
```

For dangerous tools like shell execution, file writes, or API mutation:

- Use allowlists
- Require confirmation
- Sandbox execution
- Restrict file paths
- Log all actions

---

## 9. Add memory if needed

There are two common types:

### Short-term memory

Conversation messages inside the current session.

```python
messages.append({"role": "user", "content": user_input})
```

### Long-term memory

Stored facts, preferences, or past results.

Possible storage:

- SQLite
- Postgres
- Redis
- Vector database
- Files

Example:

```python
def save_memory(user_id, fact):
    database.insert({"user_id": user_id, "fact": fact})
```

---

## 10. Add stopping conditions

Your harness should stop when:

- The model gives a final answer
- Max steps are reached
- Max tool calls are reached
- A fatal error occurs
- The user cancels
- The agent requests clarification

Example:

```python
if step >= max_steps:
    return "I could not complete the task within the step limit."
```

---

## 11. Add error handling

Handle failures gracefully:

```python
try:
    result = tool_function(**tool_args)
except Exception as e:
    result = f"Tool error: {str(e)}"
```

Also handle:

- Invalid JSON
- Tool timeout
- API errors
- Empty model responses
- Repeated tool loops
- Permission failures

---

## 12. Add logging and observability

Log each step:

```python
print({
    "step": step,
    "tool": tool_name,
    "args": tool_args,
    "result": result
})
```

In production, track:

- Model inputs/outputs
- Tool calls
- Latency
- Cost
- Errors
- User feedback
- Trace IDs

Useful tools:

- OpenTelemetry
- LangSmith
- Weights & Biases
- Custom database logs

---

## 13. Add evaluation tests

Test the harness with common cases:

```text
Simple question
Tool-needed question
Bad tool arguments
Unknown tool
Long task
Ambiguous request
Unsafe request
Model loops forever
Tool timeout
```

Example test cases:

```python
def test_agent_answers_simple_question():
    answer = run_agent("What is 2 + 2?")
    assert "4" in answer
```

---

## 14. Add human approval where necessary

For high-impact actions, require approval before execution.

Examples:

- Sending emails
- Making purchases
- Deleting files
- Updating databases
- Deploying code
- Running shell commands

Flow:

```text
Model proposes action
   ↓
Harness pauses
   ↓
User approves or rejects
   ↓
Tool runs only if approved
```

---

## 15. Package the harness behind an API

Expose the agent through an endpoint.

Example with FastAPI:

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class AgentRequest(BaseModel):
    input: str

@app.post("/agent")
def agent_endpoint(request: AgentRequest):
    result = run_agent(request.input)
    return {"result": result}
```

## Minimal agent harness checklist

```text
[ ] Define agent goal
[ ] Define tools
[ ] Create tool registry
[ ] Write system prompt
[ ] Implement model call
[ ] Implement agent loop
[ ] Parse tool calls
[ ] Execute tools safely
[ ] Return tool results to model
[ ] Stop on final answer
[ ] Add max-step limit
[ ] Add error handling
[ ] Add logging
[ ] Add tests
[ ] Add API wrapper
```

In short, an agent harness is mostly a **controlled loop** around an LLM: send context, let it choose actions, run approved tools, feed results back, and stop when the task is done.
